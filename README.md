# Оркестратор задач

Кликабельный демо-макет системы, которая сама распределяет задачи между исполнителями.

Менеджер кладёт задачу в общий пул: ТЗ с ремарками, сложность и срок. Оркестратор подбирает исполнителя по навыку, уровню и текущей загрузке. Исполнитель сдаёт работу и сразу встаёт в очередь за следующей задачей. Менеджер получает уведомление, проверяет результат и отправляет его заказчику.

**Открыть демо:** https://stanislav-perfilyev.github.io/orchestrator-demo/

Все люди, компании и задачи в демо выдуманы. Данные живут только в открытой вкладке, кнопка «Сбросить» возвращает исходное состояние.

## Как посмотреть за пару минут

Вверху переключаются три роли: **Менеджер**, **Исполнитель**, **Заказчик**.

1. **Менеджер.** В колонке «Пул» две задачи ждут исполнителя, и на карточках написано почему: аналитик не в сети, а единственный старший разработчик загружен на 9 баллов из 10.
2. Нажмите **«Новая задача» → «Заполнить примером» → «Отправить в пул»**. Оркестратор сразу назначит исполнителя, а в ленте событий справа будет видно, почему выбран именно он.
3. Включите **«Живой режим»** вверху. Исполнители начнут сдавать работу, освободившиеся будут сами получать задачи из пула, а от заказчиков будут приходить новые.
4. Откройте любую карточку в колонке **«На проверке»** и нажмите **«Отправить заказчику»** или **«Вернуть на доработку»**.
5. **Исполнитель.** Выберите Ксению Л. и включите **«На смене»**: она сразу получит задачу по аналитике, которая ждала в пуле.
6. **Заказчик.** Выберите любую компанию: заказчик видит только статус и срок своих заказов, без имён исполнителей и их загрузки.

Нажатие на исполнителя в блоке «Команда» фильтрует доску по его задачам.

## Как оркестратор выбирает исполнителя

Фильтры применяются по порядку:

1. У исполнителя есть нужный навык: дизайн, разработка, тексты, переводы или аналитика.
2. Исполнитель на смене.
3. Его уровень берёт задачу такой сложности:

   | Уровень | Сложность задач | Ёмкость, баллов |
   |---|---|---|
   | Младший | до 2 | 5 |
   | Средний | до 4 | 8 |
   | Старший | до 5 | 10 |

4. После назначения его загрузка не превысит ёмкость.

Из оставшихся выбирается тот, у кого загрузка после назначения будет самой низкой в долях от ёмкости. При равенстве задачу получает тот, у кого меньше задач в работе. Если подходящих нет, задача остаётся в пуле с объяснением причины и уходит первому, кто освободится.

Пул разбирается по сроку: сначала самые срочные задачи, при одинаковом сроке более сложные.

## Устройство

| Файл | Что внутри |
|---|---|
| `index.html` | Разметка страницы |
| `styles.css` | Стили, светлая и тёмная темы |
| `logic.js` | Правила распределения: чистые функции без DOM, работают в браузере и под Node |
| `app.js` | Интерфейс: состояние демо, три роли, диалоги, живой режим |
| `tests/logic.test.js` | Тесты правил распределения |

Сборки нет: страница открывается как есть с любого статического хостинга.

## Проверки

Нужен Node.js 22 или новее.

```bash
npm ci
npm run check
```

`npm test` прогоняет тесты логики, `npm run lint:html` проверяет разметку. Те же проверки запускаются в GitHub Actions на каждый push в `main` и на каждый pull request.
